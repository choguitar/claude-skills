# 배치 규칙과 검증

## 배치 규칙

`build.py`가 곡마다 자동으로 정한다. 우선순위 순서:

1. **한 곡은 한 페이지(두 단) 안에.** 가장 먼저 지킨다.
2. **섹션은 단 중간에서 자르지 않는다.** 섹션째로 다음 단으로 넘긴다.
3. 2를 지키면 한 페이지를 넘는 곡은 섹션 안에서 연속으로 반복되는 구간을 **도돌이표 `|: … :|`로 접는다**.
4. 그래도 넘으면 **코드 줄과 그 아래 가사 묶음**만 붙여 두고 섹션 중간에서 단을 넘긴다.
5. 그래도 넘으면 **그 곡만** 줄 간격 → 글자 크기 순으로 줄인다.
6. 한 단에 들어가는 곡은 앞 곡이 왼쪽 단만 썼으면 오른쪽 단에서, 아니면 새 페이지에서 시작한다.
7. 두 단에 걸친 곡은 **가능하면** 오른쪽 단 첫 줄을 왼쪽 단 첫 섹션 줄과 같은 높이에 맞춘다(오른쪽 단 위에 제목·곡 정보 높이만큼 빈 공간). 맞추면 한 페이지를 넘는 경우엔 생략한다 — 1~5보다 우선순위가 낮다.

도돌이표는 공간을 줄이는 수단일 뿐이다. 한 페이지에 들어가는 곡은 반복을 모두 펼쳐 쓴다 — 연주 중 되돌아가 읽을 필요가 없게.

높이는 실측값으로 추정하므로, 결과는 반드시 `check_layout.py`로 확인한다.

## 검증

빌드 출력의 `[경고]`를 사용자에게 그대로 전달한다:
- `가사가 길어 줄바꿈됨` — 자간을 한계까지 줄여도 한 줄에 안 들어간다. 가사 줄을 둘로 나누자고 제안한다.
- `코드 마디 자간 …pt로 축소` — 한 마디에 코드가 너무 많다. 읽기 어려우면 마디를 나누자고 제안한다.
- `N마디 줄을 4마디씩 나눔` — 자동 처리됨. 알리기만 한다.
- `반복 구간을 도돌이표로 접음` / `코드+가사 단위로 단을 나눔` / `글자 …pt · 줄 간격 …배로 줄임` — 한 페이지에 맞추려고 배치 규칙 3~5를 쓴 곡. 어떤 규칙을 썼는지 알린다.
- `최대로 줄여도 한 페이지를 넘음` — 곡 자체를 줄여야 한다. 섹션 생략을 제안한다.
- `둘째 단 첫 줄 높이 맞춤을 생략함` — 규칙 7을 지키면 넘쳐서 뺐다. 알리기만 한다.

그다음 Word가 실제로 배치한 결과를 검사한다:

```
python scripts/check_layout.py OUT.docx
```

`[위반]`(한 페이지 넘음, 코드·가사 분리)이 나오면 사용자에게 알리고 원인을 찾는다 — 보통 높이 실측값(`build.py`의 `LINE_HEIGHT` 등)이 서식 변경 뒤 낡은 경우다. `[참고] 섹션 잘림`은 build가 규칙 4를 쓴 곡이면 정상이다.

마지막으로 PDF로 눈으로 확인한다. Word로 만든 PDF가 실제 인쇄·배포본과 같다:

```
python scripts/export_pdf.py OUT.docx
pdftoppm -jpeg -r 80 -f 1 -l 2 OUT.pdf preview   # 앞 2쪽만 이미지로 → 열어서 확인
```

코드 줄 마디가 세로로 정렬되는지, 4번째 마디가 다음 줄로 넘어가지 않는지 본다.
